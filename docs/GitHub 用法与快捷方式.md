# GitHub 到底能拿来干什么

> 写给正在学 Python 的你。不讲概念，只讲「这玩意儿对我有什么用」。

---

## 一句话版本

**GitHub = 代码的网盘 + 时光机 + 一份会自动生长的简历。**

你平时写代码是「本地写 → 本地存」。接上 GitHub 之后变成「本地写 → 存一份到云端」。
就这一步，后面所有好处都是它长出来的。

---

## 为什么那么多人都在用

| 用法 | 对你意味着什么 |
|---|---|
| **备份** | 电脑摔了、系统重装、U盘丢了 —— 代码全在云端，换台机器 `git clone` 就回来 |
| **时光机** | 昨天还能跑，今天改崩了？`git log` 找到昨天的版本，一键回退。这是救命功能 |
| **分支实验** | 想试个新写法又怕搞坏？开个分支随便造，坏了删掉，主干一点没动 |
| **协作** | 多人写同一个项目不会互相覆盖，改了什么一目了然 |
| **看别人的代码** | 全球几亿个公开项目免费看。想学什么都搜得到现成的 |
| **被看见** | 你的仓库就是你的作品集，投简历时甩一个链接过去 |

## 你能用它干的具体 6 件事

### 1. 学期结束，你手里有「证据」，不是「我记得我学过」

别人期末复习靠回忆，你有完整的提交记录：

```
第 1 周：环境搭建
第 3 周：猜数字游戏
第 5 周：列表与字典练习
...
第 16 周：命令行记账本
```

一条条摆在那儿。**面试官和老师说"你学过什么"的时候，你不是回答，是打开一个链接。**

### 2. 贡献图（那片绿格子）

GitHub 主页有一张提交热力图，每天有提交就绿一格。
连续几十天绿下去，那张图本身就是"自律"的证明。很多 HR 第一眼看的就是它。

> 注意：绿格子只认**推送到 GitHub 的提交**，本地提交不算。
> 所以每节课结束记得推一次 —— 就是那个 `提交到GitHub.command` 双击一下的事。

### 3. 免费托管静态网页（GitHub Pages）

你以后学了 HTML/CSS，可以把仓库变成一个真网址，不用买服务器：

```
仓库 Settings → Pages → 选 main 分支 → 得到 https://xthyi.github.io/xxx
```

个人主页、作品集、课程作业展示，全免费。**这是学生最划算的福利。**

### 4. 抄……借鉴别人的代码

搜 `python 学生管理系统`、`python 爬虫 入门`，出来的全是能跑的完整项目。
看不懂的地方，一行行读，比看教程快。

> 抄之前看一眼 LICENSE。学习用没问题，直接拿去当作业交就看老师严不严了。

### 5. 交作业

很多老师现在直接要 GitHub 链接，或者让你把代码 push 到指定仓库。
现在会这套流程，比临时学的同学省一周。

### 6. 出问题能救回来

`git diff` 看改了什么，`git checkout 文件名` 撤销单个文件，`git log` 找回历史版本。
**这三招会在某次你改崩代码的深夜救你一命。**

## 老师为什么爱用

- 学生交代码不用收压缩包，不会"我发给你了你没收到"
- 能看见每次提交的时间，谁临时赶工一目了然
- 批改时可以直接在代码行上写评论
- 开源教材、课件都往 GitHub 上放，学生 clone 下来就能跑

## 你的日常操作（就三条）

**方式 A：双击**（最省事）
桌面双击 or 仓库里双击 `提交到GitHub.command`，输一句话，完事。

**方式 B：终端命令**
```bash
cd ~/Documents/python-practice
git add -A
git commit -m "第5课：列表与字典练习"
git push
```

**方式 C：我给你装的快捷命令**（新开终端窗口生效）
```bash
gpush "第5课：列表与字典"   # 一条命令：add + commit + push
github                      # 直接浏览器打开你的仓库
glog                        # 看提交历史
gback                       # 撤销所有未提交的改动（慎用）
```

**打开仓库**：桌面上的 `python-tian · GitHub.webloc`，双击直接开浏览器。

## 关于国内访问（实话实说）

- **git 走 SSH 推代码**：基本没问题，你的已经验证通过了（`ssh -T git@github.com` 返回 `Hi Xthyi!`）
- **github.com 网页**：偶尔抽风打不开，跟你的网没关系，是众所周知的原因。打不开就：
  1. 用手机热点试试
  2. 或者改 hosts
  3. 或者用镜像站（如 `hub.fastgit` 类，注意甄别安全性）
- **备选方案**：国内有个 Gitee（码云），是 GitHub 的国产平替，速度和访问都稳。
  以后要做正式项目，可以两边都推一份。

## 下一步：把门面做好

你的仓库现在有个 README，但还很素。**README 是别人点进你仓库看到的第一屏**，相当于你的脸。

期末前建议补上这几块：

1. 一句自我介绍 + 你在学什么
2. 目录结构说明
3. **进度清单**（打勾的那种，看着就爽）
4. 每个小项目一句说明 + 运行方式
5. 一张截图

写好了，这个仓库就从"我的练习本"变成"我的作品集"。

---

## 三条铁律

1. **commit message 写具体内容**，别写"更新""改了一下"。写 `"第5课：列表与字典练习"`，三个月后你才看得懂。
2. **每天推一次**，哪怕只改了一行。绿格子是攒出来的。
3. **别在公开仓库里放密码、密钥、身份证号**。这类信息一旦 push 上去，删掉提交也还在历史里。
